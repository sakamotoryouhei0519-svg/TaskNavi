# 本番の始め方と新しい版の配り方

配る係（作った人）が見る手順です。使う人に渡す説明は `user-guide.md` です（リリースのページからもリンクしています）。
配る前に、`home-test-checklist.md` の表を一通り試しておきます。

## 1. 配る zip を作る

1. `pom.xml` の `app.version` を上げる（例: `1.2.0` → `1.3.0`）。チームは全員同じ版にそろえるので、配るたびに上げます
2. テストと配布物を作る

```powershell
mvn verify
mvn -Pdist -DskipTests verify
```

3. GitHub のリリースに置く（`target\TaskNavi-（版）-windows.zip`）

```powershell
gh release create v1.3.0 "target\TaskNavi-1.3.0-windows.zip" --title "TaskNavi 1.3.0" --notes "変わったこと: …"
```

## 2. 各パソコンに入れる

- [ ] リリースのページから zip をダウンロードし、`C:\TaskNavi` など短い場所に展開する
- [ ] **Google ドライブの中には置かない。** アプリのフォルダは各 PC に1つずつ置きます。共有するのはプロジェクトのフォルダだけです
- [ ] `TaskNavi\TaskNavi.exe` を右クリック →「送る」→「デスクトップ（ショートカットを作成）」
- [ ] 初めて起動すると「発行元不明」の警告が出ることがある。「詳細情報」→「実行」
- [ ] Java を入れる必要はありません（アプリの中に入っています）

データ・バックアップ・ログは各 PC の `%APPDATA%\TaskNavi` に置かれます。アプリのフォルダを消したり入れ替えたりしても消えません。

## 3. 見本のデータを消す

初めて起動すると、見本のプロジェクト（「次世代ECサイトリニューアル」など）が入っています。

- [ ] 「自分だけのタスク」を選び、WBS で見本のプロジェクトを選んで「削除」。中の工程とタスクも一緒に消えます。プロジェクトの数だけ繰り返す
- [ ] 全部消して空にしても、次に起動したときに見本が戻ることはありません（見本を入れるのは、データベースを初めて作ったときの1回だけ）

見本をもう一度見たくなったら、アプリを閉じて `%APPDATA%\TaskNavi\tasknavi.db` を別の名前に変えて起動します（新しいデータベースになり、見本が入ります）。元に戻すときは名前を戻します。

## 4. 共有プロジェクトを始める

1. 代表の1人が「プロジェクト ▼」→「新しい共有プロジェクトを作る」で、Google ドライブの中に作る（共有ドライブが使えればそこ、なければ `G:\マイドライブ`）
2. ブラウザの Google ドライブで、できたフォルダをメンバーに「編集者」で共有する。見るだけの人は「閲覧者」
3. マイドライブに作った場合、メンバーは「共有アイテム」からそのフォルダを右クリック →「ショートカットを追加」で、自分のマイドライブに置く
4. メンバーは「プロジェクト ▼」→「共有フォルダから参加する」でそのフォルダを開く
5. 全員、「プロジェクト ▼」のメニューで表示名を決める。担当者の欄にはこの名前が入り、「今日」タブの「自分の担当だけ」もこの名前で決まります
6. ヘッダーが「メンバー ○人」になれば始められます

始める前の1〜2週間で、今のやり方の数（進み具合の確認にかかる時間、期限を過ぎて気づいたタスクの数など）を `results-log.md` の1章に書いておきます。始めた日は2章、そのあとは毎週3章を書きます。

## 5. 新しい版を配る

- [ ] 1章のとおり zip を作ってリリースに置く
- [ ] 自分の PC を新しい版に入れ替えて、共有プロジェクトを開く。これで共有フォルダに自分の版が書かれ、古い版の人のヘッダーに数十秒で「新しい版 ○.○.○ があります」と出ます。押すと入れ替え方とリリースのページを開くボタンが出ます
- [ ] 念のため全員にも「アプリを閉じて、`C:\TaskNavi` の中の `TaskNavi` フォルダを消してから、新しい zip を展開して起動してください」と伝える（上書きより確実）。データは消えません
- [ ] 「メンバー ○人」を押すと、各自の版が出ます。古い版の人はオレンジなので、全員がそろったかをここで確かめます
- [ ] 新しい版で記録の形が変わったときは、古い版の人に「アプリの更新が必要」も出ます。古い版ではその記録が読めないので、早めに入れ替えてもらいます
- [ ] 新しい版で初めて起動すると、データベースの形が自動で新しくなります（Flyway）。前の日のバックアップは `%APPDATA%\TaskNavi\backups` に残っています

## 6. 困ったとき

不具合や要望が出たら、`results-log.md` の4章に1行足します（直したら、直した版と日数も）。

| こんなとき | 見る所・すること |
|---|---|
| エラーが出た | `%APPDATA%\TaskNavi\logs` のいちばん新しいファイルを送ってもらう |
| データを前の日に戻したい | `home-test-checklist.md` の「4. バックアップから戻す」の手順（7日分あります） |
| 共有の変更を消してしまった | 「プロジェクト ▼」→「変更履歴」から元に戻す |
| 2人の変更が重なった | ヘッダーのオレンジの「重なった変更」を押して、どちらの値にするか選ぶ |
| 他の人の変更が出てこない | Google Drive for desktop が同期中か確かめる。ツールバーの「更新」を押す |
| 英語で表示される | Windows の表示言語が英語になっている。日本語にしたい場合はその PC の言語設定を見る |
