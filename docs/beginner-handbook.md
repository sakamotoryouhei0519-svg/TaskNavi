# TaskNavi 初学者向け教科書

勉強を始める人は、先に **「12. 最初の2週間」** だけを上からやる。  
1〜11章と [study-checklist.md](./study-checklist.md) は辞書です。最初から最後まで読まない。

## 1. このプロジェクトで最初に押さえること
- 画面は Swing で作っています。Java に最初から入っている画面の部品です
- 部品の並べ方は、ほとんど MigLayout で決めています
- 画面ごとに、受け持つ仕事が分かれています
- 画面はデータを `TaskService` に頼みます。データベースを触るのは `Dao` だけです
- ある画面で変えたことは、`TaskEventBus` が他の画面に知らせます

## 2. 全体構成の考え方

フォルダは役割で分かれています。いちばん上には、起動の `Main`、エラーの `AppException`、文言の `AppMessages`、アプリの版の `AppVersion` だけを置きます。

- `model` はデータの形（`Task` など）
- `service` は保存やログインの仕事（`TaskService`、`AuthService`、期限の判定の `DueTasks`）
- `persistence` は自分だけのタスクのデータベース（`Database`、`TaskDao`）
- `team` は共有プロジェクトの記録の読み書き（`TeamProject`。16章）
- `io` は CSV と JSON の読み書き（`TaskCsv`、`TaskJson`）
- `util` は絞り込みと状態の小さな計算（`TaskViewFilter`、`TaskStatusCycle`）
- `event` は画面への知らせ（`TaskEventBus`）
- `ui` は画面。直下には、どの画面でも使う部品（`AppTheme`、`AppDialog`、`DatePickerDialog` など）を置きます。中は次のフォルダに分かれます
  - `ui/main`: メインの窓（`MainFrame`）と、ヘッダー・検索欄などその部品
  - `ui/today`・`ui/wbs`・`ui/kanban`・`ui/gantt`・`ui/calendar`: 5つのタブ
  - `ui/taskdialog`: タスクを作る・直す窓
  - `ui/team`: 共有プロジェクトの画面（「プロジェクト ▼」の `ProjectSwitcher` など）
  - `ui/auth`: ログイン・登録・パスワード再設定

## 3. よく出てくる名前
- `JFrame` はウィンドウ、`JDialog` は小さな窓、`JPanel` は部品を入れる箱
- `MigLayout` は部品の並べ方
- `ActionListener` はボタンを押したときの処理
- `LocalDate` は日付
- `TaskService` は保存の窓口、`TaskDao` はデータベース
- `persistence` の中の `TaskRowMapper` / `TaskHierarchySupport` / `TaskCrudDao` / `TaskImportDao` は、データベースの読み書きを分担しています
- `TaskEventBus` は他の画面への知らせ
- `AppTheme` は色、`AppMessages` は画面の文言
- `IconManager` はアイコン
- `SearchablePanel` は、上の検索欄で絞り込める画面の印

## 4. MigLayout の見方
- `fill`: 使える場所いっぱいに広げる
- `insets`: 外側の余白
- `gap`: 部品と部品のすき間
- `wrap`: そこで次の行に行く
- `grow`: 余った場所に合わせて伸びる
- `align right/left/center`: 右・左・真ん中に寄せる

## 5. 画面ごとの重要ポイント
### LoginFrame / RegisterFrame / ResetPasswordFrame（`ui/auth`）
- ログイン、新規登録、パスワード再設定の画面です
- ログインの判定は `AuthService` です。何度も間違えると、しばらく試せなくなります
- 見た目は `AppTheme` と `AuthFormWidgets` でそろえています
  - 3 画面とも「背景の上に角丸カード 1 枚、その中に縦一列」の形です。`createCard()` に部品を `gaptop` で並べ、`showCard()` が中身に合わせてウィンドウサイズを決めます（`pack`）
  - 入力欄の色は `AppTheme.applyTextColors()` で本体画面と共通です。パスワード欄（`JPasswordField`）は `TextField.*` の既定色が効かないので、必ずこれを通します
  - エラー文は `createErrorArea()`（文字単位で折り返す読み取り専用テキスト）に出します。高さを常に確保しているので、エラーが出ても画面が動きません
  - パスワード表示切替の目のアイコンとチェックボックスは `AuthIcons` で描いています（絵文字は環境で見た目が変わるため）
- 登録できるパスワードの決まりは `AuthPasswordPolicy` です

### MainFrame
- アプリ全体の土台です
- いちばん上の帯（ヘッダー）に、ユーザー名・インポート／エクスポート・テーマ・ログアウトがあります。その下の帯（ツールバー）に、検索と絞り込みがあります
- 真ん中はタブです: 今日 / WBS / カンバン / ガント / カレンダー
- 最後に開いたタブを名前で覚えていて、次に起動したときもそのタブから始まります（`Preferences`）。初めては「今日」から始まります
- 上の検索欄の文字は、各タブの `SearchablePanel` に渡ります
- 今かかっている絞り込みの説明文は、`MainGlobalSearchBar.describeFilters` が作ります
- エクスポート／インポートは `TaskDataIoHelper` です。形式は CSV（Excel で編集する用）と JSON（TaskNavi 同士で移す用）
  - エクスポートでは、全件か、絞り込んだ分だけかを選べます。絞り込んだときも親（プロジェクト・工程）は一緒に書き出します。親がないと取り込み直したときに階層が組めないためです
  - CSV の読み書きは `io/TaskCsv`、区切り・引用符・文字コードの細かい処理は `io/CsvCodec` です。書き出しは BOM 付き UTF-8（Excel で文字化けしない）、読み込みは UTF-8 と Shift_JIS（Excel の普通の保存）の両方を受け付けます
  - 日付は `2026-10-24` / `2026/10/24` / `2026年10月24日` のどれでも読めます。状態・優先度は「進行中」「高」のような日本語で書きます
  - 親子関係は「ID」「親ID」列で表します。取り込むときは ID を振り直し、親を先に保存してから子の親 ID を新しい ID に付け替えます（`TaskImportDao`）
  - 読めない行があっても、ほかの行は取り込めます。取り込む前に件数と「何行目がなぜ駄目か」を出し、「今のタスクに追加」か「すべて置き換え」を選びます。置き換えのときは、消す前のタスクを `backups` フォルダに `before-import-日時.csv` として残します
  - `=` `+` `-` `@` で始まる値は Excel が数式として実行してしまうので、書き出し時に先頭へ `'` を付け、取り込み時に外します
- MainFrame が長くならないよう、部品ごとに別のファイルにしています
  - ヘッダー: `MainHeaderBar`
  - 検索欄: `MainGlobalSearchBar`
  - テーマの切り替え: `MainThemeSupport`
  - ツールバーのボタン: `MainToolbarButtons`
  - 追加の流れ: `MainTaskAddHelper`
  - タブの見た目: `MainTabChrome`

### TodayPanel（`ui/today`）と期限の通知
- 期限切れ・今日まで・7日以内の、終わっていないタスクを並べます。子を持つタスクは出しません
- 自分だけのタスクと、最近開いた共有プロジェクトのタスクを、まとめて出します。プロジェクトが2つ以上あると、名前の横にどのプロジェクトかの札が付きます（くわしくは16章）
- どれをどこに入れるかは `service/DueTasks` が決めます。画面と通知で同じものを使います
- 共有プロジェクトを使っていると、右上に「自分の担当だけ」が出ます。初めはオンで、共有プロジェクトのタスクは、担当者が自分の表示名か空のものだけを出します。自分だけのタスクは全部出します。期限の通知も同じ設定で数えます（`TodayPanel.onlyMine`、`TaskSource.isMine`）
- 「完了」ボタンは `TaskStatusChanger`、ダブルクリックの編集は `TaskEditHelper` を通ります。どちらも、そのタスクのプロジェクトの `TaskService` に書きます
- `DueReminder` が、起動したときと日付が変わったときに、Windows の通知で件数を知らせます。件数も全部のプロジェクトの合計です。日付が変わったら全画面を描き直させます

### WbsPanel / KanbanPanel / GanttPanel / CalendarPanel
- 仕事の中心になる4つの画面です。どれも `TaskService` を受け取ります
- 置き場所は `ui/wbs`、`ui/kanban`、`ui/gantt`、`ui/calendar` です
- 見るところは、タスクの一覧、状態、操作ボタンのつながりです
- 画面の描き直しは、`refresh` で始まるメソッドと `TaskEventListener` を見ます
- 期限切れは `Task.isOverdue()` です。終わっていなくて、終了日が今日より前なら期限切れです。カレンダーとカンバンのカードで目立たせます
- どの画面も、1つのファイルに全部は書いていません。同じフォルダの中で分けています
  - WBS: ツリーの組み立て、絞り込み、ドラッグでの並べ替え、右側の詳細、登録
  - カンバン: 絞り込み、カード、列への振り分け
  - カレンダー: 月や週の切り替え、月表示と週表示、日ごとの横の一覧、カード
  - ガント: 線の描画、クリックした場所の判定、ドラッグ、横の列
- 状態を1つ前・1つ後ろへ動かすのは `util/TaskStatusCycle` です

### TaskDialog
- タスクを作るときと直すときの窓です（`ui/taskdialog/TaskDialog`）
- 種類は `EntryType` で、プロジェクト・フェーズ・タスクの3つです
- 日付の欄は `DatePickerDialog` と一緒に動きます
- 新しく作るタスクの中身は `TaskEntryFactory` も見ます
- 親の選択肢、入力欄、保存前のチェックは、同じフォルダの別ファイルにしています
- 一番下にメモ欄があり、改行して何行でも書けます。メモ欄の中では `Tab` で次の欄へ移り、`Ctrl+Enter` で保存します
- メモはデータベースの `memo` 列に入ります（`V5__task_memo.sql`）。WBS の右側の詳細と、今日タブの行にマウスを乗せたときにも出ます

### キーボード操作（`MainFrame.installShortcuts`）
- `Ctrl+F`: 検索欄へ移る
- `Ctrl+N`: タスクを追加する
- `Enter`: 選んでいるタスクを編集する（`TaskEditHelper` で開きます）
- `Delete`: 選んでいるタスクを消す
- 文字を入力している途中は、`Enter` と `Delete` は効きません

### DatePickerDialog（`ui/DatePickerDialog`）
- 日付を選ぶ小さな窓です。いろいろな画面で使い回します
- 見るところは、`LocalDate` で月を進めたり戻したりするところと、日付のボタンを作るところです

### 検索（`ui/main/MainGlobalSearchBar`）
- 上の検索欄に1文字入れるたびに、今の画面を絞り込みます
- タスク名だけでなく、担当者の名前やメモの中身でも見つかります（`TaskViewFilter.matchesKeyword`）。WBS も同じ判定を使います
- 各画面は `SearchablePanel` の `applySearchFilter` を持っています

## 6. よく見る書き方
- `getSelectedItem()` で、コンボボックスで選ばれている項目を取る
- `setText` で入力欄に文字を入れ、`getText` で取り出す
- `addActionListener` で、ボタンを押したときの処理を登録する
- `setVisible(true)` で窓を出す
- `dispose()` で窓を閉じる
- `LocalDate.parse()` で文字を日付に変える。変えられなければ、日付の書き方がおかしい
- 状態などの画面の文字は `AppMessages` から取ります。データベースには `NOT_STARTED` のような英語のコードで保存します

## 7. まちがえやすいところ
- `null` かどうかを確かめずに使うと、アプリが落ちます
- `JComboBox` の中の値（コード）と、画面に出す文字がずれると、おかしな動きになります
- `wrap` を忘れると、部品が横にずっと並びます
- ダークモードでは、背景の色と文字の色の両方を確かめます。複数行の入力欄は `AppTheme.createStyledTextAreaScroll` で作ると、他の入力欄と同じ色になります
- 縦にスクロールする一覧や詳細は、`WidthTrackingPanel` の上に置きます。置かないと、長い名前で横にはみ出し、右端のボタンが切れます。縮めてよい文字には MigLayout で `wmin 0` を付けます
- 窓は 960×560 より小さくできません（`UiConstants.WINDOW_MIN_WIDTH_MAIN`）。画面を直したら、この大きさでも切れないか確かめます
- 画面から `TaskDao` を呼ばない。必ず `TaskService` を通します
- 本番の `TaskService` は `TaskService.createDefault()` で作ります。画面が `new TaskDao()` することはありません
- GitHub Actions（`.github/workflows/ci.yml`）で `mvn test` が動きます。自分のパソコンでも同じコマンドで確かめます
- 画面の土台を壊していないかは `MainFrameSmokeTest` で確かめます。タブの切り替え、検索欄を空にすること、テーマの切り替えを試しています

## 9. 設計の決まり
- 画面は、見せることと入力を受けることだけにします
- 「追加する」「消す」などの仕事は `TaskService`、データベースへの読み書きは `Dao` に置きます
- 何度も使う処理は1か所にまとめます（`TaskBusinessRules` / `SearchFilterUtil` / `TaskViewFilter` など）
- 色は `AppTheme`、文言は `AppMessages` から取ります
- 確認や選択の窓は `AppDialog` を使います。タスク編集の窓と同じ見た目になります
- フォルダの分け方は2章のとおりです。画面のフォルダは、WBS やガントごとにさらに分かれます
- 使わなくなったクラスやメソッドは、残さずに消します。残すと、どれが本物の処理か読む人が迷うためです（検索は `TaskViewFilter` だけ、入力チェックは `TaskWriteValidator` と `TeamProject` だけ）

## 11. データが守られている約束

画面は、データベースへ直接書きません。必ず `TaskService` を通ります。

- 保存に成功したときだけ、他の画面へ「変わったよ」と知らせます（`TaskEventBus`）
- 入力が不正なら、1件も書きません。画面には理由が出ます
- 編集の保存は `updateTask` です。中で `updateTasks` を1回呼び、成功したあとだけ他の画面へ知らせます
- 削除は、子タスクも含めて1回で消します。途中で失敗したら、全部元に戻します
- 消したあと10秒間、画面下の帯に「元に戻す」が出ます。押すと、子タスクも含めて元の ID のまま戻ります（`TaskService.restoreDeleted`）。その間に親が消されていたら、戻しません
- 並べ替えも1回で保存します
- パスワード再設定の番号は、データベースに5分間残ります。アプリを閉じても、その間は有効です
- タスクは、ログインした人のものです。別のアカウントのタスクは、一覧にも検索にも出ません
- データベースは `%APPDATA%\TaskNavi\tasknavi.db` に置きます。どのフォルダから起動しても同じです（`AppDataLocation`）
- 起動するたびに、その日の分がまだなければ `backups` フォルダにコピーを取ります。7日分残します（`DatabaseBackup`）。戻すときは、アプリを閉じてから、そのコピーを `tasknavi.db` という名前で上書きします
- ログは `%APPDATA%\TaskNavi\logs` に残します。今日の分は `tasknavi.log`、前の日の分は日付付きのファイルで、14日分だけ残します（`logback.xml` と `LogDirectoryDefiner`）。困ったことが起きたら、まずここを見ます。テストのときはファイルに書きません（`src/test/resources/logback-test.xml`）
- 読み込んだ全件は、次の書き込みまで `TaskService` が使い回します。書き込みは必ず `TaskService` を通るので、古いままにはなりません。ツールバーの更新ボタンで読み直せます

失敗の文面は `AppException` が持ちます。裏側の処理（`SwingWorker`）が包んでも、`ErrorDialogUtil.findAppException` が取り出して画面に出します。

## 12. 最初の2週間

平日だけ、1日に1個。全部で10日です。ファイルは全部読まない。  
IntelliJ でファイルを開き、`Ctrl+F` で下に書いた言葉を探す。メソッド名を `Ctrl+クリック` すると、その中身に飛べる。

ノートは1行でよい。その日の最後に、下の「今日の終わり」が言えたら終了。  
追加・編集・削除は、別々の保存講座ではありません。道は毎回 `TaskService` のあと `TaskEventBus` です。違うのはメソッド名だけです。

### 1日目: 起動する

アプリを起動する。ログインして、タブが5つあることを見る。  
ログインを飛ばす起動は、実行設定に `-Dtasknavi.skipLogin=true` を付ける。

1. `Main.java` を開く
2. `main` を検索する
3. スプラッシュのあと、ログインを飛ばすか、ログイン画面へ進むことを見つける

今日の終わり: 「起動のあと、ログインした人の画面に進む」と言える。

### 2日目: ログインした人のタスクだけ

ログインしてメイン画面を開く。別のアカウントでは、一覧が違うことを意識する。

1. `ui/auth/LoginFrame.java` を開く
2. `UserSession.login` を検索する
3. その直後の `TaskService.createDefault` を `Ctrl+クリック` する
4. ログイン中のユーザーから台帳を作っていることを見る。今日はここまで

今日の終わり: 「画面は `new TaskDao()` しない。ログインした人の `TaskService` を使う」と言える。

### 3日目: タスクを1件追加する

画面の「追加」を押して、タスクを1件作る。カンバンにも同じ名前が出ることだけ見る。イベントの中身は明日。

1. `ui/main/MainFrame.java` を開く
2. `addTaskButton` を検索する
3. その行が `MainTaskAddHelper.showAndAdd` を呼んでいることを確認する
4. `showAndAdd` を `Ctrl+クリック` する
5. その中で `TaskDialog` と `taskService.addTask` を見つける

今日の終わり: 「追加ボタンは、ダイアログで入力させて、`TaskService.addTask` に渡している」と言える。

### 4日目: 他の画面が追いつく理由

昨日追加したタスクが、別のタブにも出る理由をコードで見る。

1. `service/TaskService.java` を開く
2. `addTask` を検索する
3. `taskDao.addTask` のあとに、`TaskEventBus` へ知らせている行を見つける
4. `post` を `Ctrl+クリック` して、`TaskEventBus.java` に入る
5. `ui/wbs/WbsPanel.java` で `taskEventListener` を検索し、知らせを受けたら `refreshWbs` していることを見る

ノートにこの1行を書く。

`追加ボタン → MainTaskAddHelper → TaskDialog → TaskService.addTask → TaskEventBus → 各画面`

今日の終わり: この1行を、ノートを見ずに言える。

### 5日目: 編集は同じ道

WBS でタスクを選び、名前を変えて保存する。カンバンの名前も変わることを見る。空の名前では保存できないことも見る。

1. `WbsPanel.java` で `openEditDialog` を検索する
2. 最後の方で `taskService.updateTask` を呼んでいることを見る
3. `service/TaskService.java` の `updateTask` を開く。中で `updateTasks` を呼んでいる
4. `updateTasks` の保存が終わったあとで `TaskEventBus` に知らせていることを見る

今日の終わり: 「編集は追加と同じ道。違うのは `addTask` ではなく `updateTask`。成功したときだけ、他の画面に知らせる」と言える。

### 6日目: 削除

ツールバーの削除で、今のタスクを消す。子がある場合は子も消える、と画面下の確認の帯に書いてあることを読む。「はい」を押すまで消えません。

## 16. チームで使う（`team` フォルダ）

サーバーを置かずに、Google ドライブの共有フォルダ（Google Drive for desktop）を通して数人で同じタスクを見る仕組みです。画面左上の「プロジェクト ▼」で共有プロジェクトを選ぶと、今日・WBS・カンバン・ガント・カレンダーのどのタブにも、そのプロジェクトのタスクが出ます。「自分だけのタスク」を選ぶと、いつもの個人のタスクに戻ります。

共有プロジェクトを開いているあいだ、ボタンの右に「メンバー ○人」「同期中」が出ます。互いに知らずに変更が重なると、オレンジの「重なった変更 ○件」が出ます。メンバー・重なった変更・変更履歴・表示名の変更は、どれも「プロジェクト ▼」のメニューからも開けます。

### 全タブで共有プロジェクトを見る仕組み

```
各タブ → TaskService → TaskStore ─┬─ TaskDao        （自分だけのタスク。SQLite）
                                  └─ TeamTaskStore  （共有プロジェクト。TeamProject）
```

- タブはどれも `TaskService` からしか読み書きしません。`TaskService.useStore` で保存先を差し替えて `reload()` すると、どのタブも描き直されます。タブの側は何も変えていません
- 差し替えるのは `MainFrame` です。`ui/team/TeamSession`（開いている共有プロジェクトの係。画面は持たない）がプロジェクトを開いた・閉じたときに `TeamSession.Listener.projectChanged` を呼ぶので、そこで `TeamSession.storeOf(project)` を渡します。保存先はプロジェクトごとに1つだけ作り、切り替えて戻ってきても同じものを使うので、タスクの番号が変わりません。左上のボタンとメンバー・同期・重なりの表示は `ui/team/ProjectSwitcher`
- 担当者の欄の横のボタンから、メンバーの名前を選べます。`TaskDialog` が `TaskService.assigneeOptions()` を聞き、共有プロジェクトなら `TeamTaskStore` がメンバーと、メンバー以外の担当者（社外の人など）を返します。自分だけのタスクでは空なのでボタンは出ません
- 共有のタスクの ID は UUID ですが、画面は int で扱うので、`TeamTaskStore` が番号を振ります。番号はアプリを閉じるまで変えません。読み直すたびに振り直すと、選んでいたタスクが別のタスクにすり替わるからです
- `TeamTaskStore` は渡したタスクに、そのとき見せた状態の版（`Task.revision`）を付けます。保存のときはその版の状態と比べるので、編集画面を開いたあとに届いた他の人の変更は、黙って上書きせず「重なり」として残ります。変わっていない項目は記録に書きません
- WBS で親を変えると `PARENT` の変更として書きます。階層の深さは記録に書かず、並べるときに親のたどり方から決めます（`TeamReplay`）。自分の下への移動と、3段を超える移動は `TeamProject.requireMovable` が断ります。2人が同時に逆向きに動かして輪になったときは、輪の中で最初に作られたタスクを一番上に出します
- 他の人の変更が届くと、`TeamSession` の自動の読み直しが `Listener.dataChanged` を呼び、`TaskService.reload()` で全タブが描き直されます。ツールバーの「更新」と、ヘッダーの「同期中」を押したときも、共有フォルダを読み直します
- 自動の読み直しと前回のプロジェクトを開くのは `TeamSession.start()` で、`MainFrame.startDueReminders` から呼びます。コンストラクタで始めると、画面のテストが本物の共有フォルダを読みに行くためです。ログアウトでは `MainFrame.dispose` が `TeamSession.stop()` を呼び、読み直しを止めます
- 以前は「チーム」タブにチーム用の一覧と編集画面がありましたが、全タブで共有プロジェクトを扱えるようになったのでなくしました。同じことをする画面が2つあると、どちらを使えばよいか迷うためです

### 「今日」タブと期限の通知は全プロジェクト

WBS などは選んでいる1つのプロジェクトだけを出しますが、「今日」タブと期限の通知は、自分だけのタスクと最近開いた共有プロジェクトをまとめて出します。毎朝どのプロジェクトを開くか考えずに済むようにするためです。

```
TodayPanel / DueReminder → ProjectSources.all() → TaskSource（名前・今選んでいるか・TaskService）の一覧
                                                   ├─ 今選んでいるプロジェクト（MainFrame の TaskService）
                                                   ├─ 自分だけのタスク（共有プロジェクトを選んでいるとき）
                                                   └─ ほかの共有プロジェクト（TeamSession.otherProjects()）
```

- 選んでいないプロジェクトにも、それぞれ専用の `TaskService` を作ります（`ui/main/ProjectSources`）。`MainFrame` の `TaskService` は1つしか保存先を持てないためです。保存先ごとに1つだけ作って使い回します
- `TeamSession` は、最近開いたプロジェクトも裏側で開いて持っておきます（`loadOthers`）。5 秒ごとの読み直しでそちらも見て、変わっていたら `Listener.otherProjectsChanged` を呼びます。`MainFrame` はそこで `TaskService.reload()` を呼び、「今日」タブを描き直させます
- 番号（ID）はプロジェクトごとに 1 から振るので、別のプロジェクトで同じ番号が出ます。そこで `DueTasks` はプロジェクトごとに作ってから `DueTasks.merge` でつなぎます。全部を混ぜてから作ると、あるプロジェクトの1番を、別のプロジェクトの1番の親と取り違えます（`DueTasksTest.mergeKeepsEachProjectsParentsApart`）
- 「今日」タブでは、行ごとにどのプロジェクトの `TaskService` かを覚えています。Enter と Delete のキーも、`SearchablePanel.selectedTaskService()` で選んだ行のプロジェクトに書きます
- 期限の通知は、`TeamSession.start` が裏側で共有プロジェクトを開き終わってから始めます。先に始めると、最初の通知に共有プロジェクトの分が入らないためです
- 開けなかったプロジェクト（ドライブがまだ準備中など）は、黙って飛ばします
- 「自分の担当だけ」がオンのときは、共有プロジェクトのタスクのうち、担当者がチームの表示名と同じもの（前後の空白と大文字・小文字は無視）と、担当者が空のものだけを出します。空のものも出すのは、誰も担当していない期限に誰も気づかなくならないためです。比べるのは `TaskSource.myName`（`ProjectSources` が表示名を入れる）で、自分だけのタスクは `null` なので全部出ます
- 親かどうかは、絞る前の全件で決めます（`DueTasks.of(tasks, today, include)`）。先に絞ると、ほかの人が担当する子を持つ親が、子のないタスクに見えて出てしまいます
- 表示名を変えると、開いている全部の共有プロジェクトで名前が変わります。前の名前が担当のタスクがあれば「担当者も直しますか？」と聞き、「はい」なら全部を新しい名前に付け替えます（`TeamSession.changeDisplayName` → `TeamProject.reassign`。プロジェクトごとに1回で書きます）。「いいえ」にすると、前の名前のタスクは「自分の担当」から外れます
- 担当者名の比べ方（前後の空白と大文字・小文字を無視）は `model/Assignees.same` の1か所です。「自分の担当だけ」と付け替えの両方が使います

### インポートを速くする

CSV や JSON から共有プロジェクトへ大量に取り込むときは、1件ずつ追加せず `TeamProject.importTasks` でまとめて書きます。

- 1件ずつだと、そのたびにファイルを開いて1行足し、ディスクに書き切り（force）、全部の記録を頭から当てはめ直します。件数が増えるほど遅くなり、Google ドライブ上ではとくに遅くなります
- `importTasks` は、先に全部の行をチェックし、1つでもだめなら何も書きません（エラーは「3 件目: 」のように何件目かを付けます）。通ったら `TeamChangeLog.appendAll` で全部の行を1回で書き、当てはめ直しも1回だけです
- 「置き換え」のときは、今あるタスクの削除の記録も同じ1回で書きます
- 親子は、取り込む行の中の何件目が親か（`ImportDraft.parentIndex`）で表します。共有のタスクの ID は書いてみるまで決まらないためです

### 記録の仕組み

```
プロジェクトのフォルダ\        ← このフォルダをメンバーだけに共有する
   ├─ project.json            （プロジェクト名）
   ├─ members\
   │    ├─ tanaka-1a2b3c.json （田中さんの PC の表示名。田中さんの PC しか書かない）
   │    └─ suzuki-4d5e6f.json
   └─ changes\
        ├─ tanaka-1a2b3c.jsonl（田中さんの PC が書いた変更。田中さんの PC しか書かない）
        └─ suzuki-4d5e6f.jsonl
```

- ファイル名の `tanaka-1a2b3c` は端末 ID です。PC ごとに一度だけ作り、Windows の設定に保存します（`TeamSettings`）。同じ人が2台で使っても、別のファイルになります
- 表示名・最近開いたプロジェクト・前回開いていたプロジェクトも `TeamSettings` が覚えます。起動時、前回のプロジェクトを裏側で開きます。ドライブがまだ準備中なら、黙って何もしません
- プロジェクトを作る・参加する・読み直す・重なりを戻すときの読み書きは、`TeamSession` が裏側の1本の列（`team-io` スレッド）に順番に並べます。ネットワークドライブが遅くても画面は止まらず、書き込みの途中に読み直しが割り込むこともありません。作る・表示名の入力の画面は `TeamDialogs`、メンバーの一覧は `TeamMembersDialog`
- 親タスクの進捗と状態は、記録に書かずに表示のたびに子の平均から出します（`TeamReplay.rollUpProgress`）。書くと、子を変えた人全員が親も書き換えることになり、重なりが増えるためです

- 変更は1件ずつ、自分のファイルの最後に1行足すだけです（`TeamChangeLog.append`）。1つのファイルを2台が書かないので、同期で「競合したコピー」ができません
- データベースを共有フォルダに置かないのは、同期の途中のファイルを別の PC が開くと壊れるからです
- 全員のファイルを読み、決まった順に並べて頭から当てはめると、今の一覧になります（`TeamReplay`）。同じファイルからは、どの PC でも同じ結果です
- 並べる順は PC の時計ではなく `clock` という番号です。相手の変更を見たあとの変更は、必ず後ろに並びます
- 2人が互いの変更を知らずに同じ項目を変えたら、後ろに並んだ方を使い、消えた方の値を `TeamConflict` に残します。別の項目なら両方使います
- 「知らずに」は、変更の記録に「この値を見て変えた」という元の記録の ID（`base`）を一緒に書いて判定します。編集画面を開いている間に自動の読み直しが入っても、開いた時点の状態（`TeamState`）を `updateTask(id, 変更, 見ていた状態)` に渡すので、見ていなかった変更は重なりとして残ります
- 画面は 5 秒ごとに `TeamProject.reloadIfChanged` を呼びます。`changes` と `members` のファイルの大きさと更新時刻（`TeamChangeLog.fingerprint`）が前回と同じなら、読まずに終わるので軽い処理です。ただし、相手の PC から Google ドライブ経由で届くまでに 10〜60 秒ほどかかるので、相手の変更が見えるまでの時間はほぼそちらで決まります
- 重なりがあると、ヘッダーにオレンジの「重なった変更 ○件」が出て、押すと見比べる画面が開きます（`TeamConflictDialog`）。1回の保存で複数の項目が重なったら1件にまとめます（`TeamConflictGroup`）。「〇〇さんの値に戻す」は消えた値を普通の変更として書き直し、「タスクを戻す」は削除を取り消す `RESTORE` の記録を書きます（`TeamProject.restoreTask`。消えている親と子もまとめて戻します）
- 「このままでよい」は、その PC だけで覚えます（`TeamSettings.acknowledge`）。記録には書かないので、他の人の画面には残ります。覚える印は `TeamConflict.key()` で、何度読み直しても同じ値になるように作っています
- チームのタスクを削除したあとの「元に戻す」も `restoreTask` です。消した記録は消さずに、戻した記録を足します
- 「プロジェクト ▼」→「変更履歴」で、誰がいつ何を何から何に変えたかを新しい順に見られます（`TeamHistoryDialog`）。中身は `TeamHistory.build` で、記録を一覧と同じ順に当てはめ直しながら、項目ごとの前後の値を拾っています。時刻は書いた人の PC の時計なので、並び順（`clock`）と時刻が前後することがあります
- 同じ PC で TaskNavi を2つ起動すると、2つが同じ記録ファイルに同時に書きに行き、行が壊れます。`TeamChangeLog.append` は PC 内の一時フォルダのファイルでロックを取ってから書きます。共有ドライブ上のファイルはロックが効くとは限らないためです。`TeamChangeLogConcurrencyTest` が別々の JVM で再現しています

- 同期の途中で切れた行は読み飛ばし、次に読んだときに読めます

### アプリの版をそろえる

全員が同じ版の TaskNavi を使う前提です。記録の形が違う版が混ざると、人によって見える一覧が変わります。

- 記録の1行ごとに形の番号（`v`）を書きます（`TeamEventCodec.FORMAT`）。項目や `Op` を足して記録の形を変えたら、この番号を上げます
- 古い版のアプリは、自分より大きい番号の行を読まずに数えます（`TeamChangeLog.ReadResult.newerFormatLines`）。同期の途中で切れた行（`unreadableLines`）とは分けて数えます。切れた行は待てば読めますが、新しい形の行はアプリを新しくするまで読めないためです
- 新しい形の行があると、ヘッダーがオレンジの「アプリの更新が必要」になり、マウスを乗せると行数と今の版が出ます（`ProjectSwitcher.refresh`）
- アプリの版は `pom.xml` の `app.version` です。配布用の JAR の manifest に書き、`AppVersion.current()` が読んでウィンドウのタイトルと起動時のログに出します。IntelliJ から動かしたときは manifest が無いので「開発版」と出ます。新しい版を配るときは、`app.version` を上げてから exe を作ります
- 入口は `TeamProject`（作る・開く・追加・変更・削除・読み直し）。テストは `TeamProjectTest` で、2つのフォルダ間でファイルをコピーして「同期の遅れ」や「オフラインで同時に編集」を再現しています

### 置き場所

- 「共有ドライブ」は、その Google アカウントがどこかの共有ドライブのメンバーでないと `G:\` に現れません。個人の Google アカウントでは作れず、会社のアカウントでも管理者が作成を止めていることがあります
- そのときは `G:\マイドライブ` の中に作り、できたフォルダをブラウザの Google ドライブで、メンバーに「編集者」として共有します。メンバーは共有されたフォルダを「ショートカットを追加」で自分のマイドライブに置くと、`G:\マイドライブ\...` から開けます
- 「新しい共有プロジェクトを作る」の場所の初期値は、共有ドライブ → マイドライブ → ホームフォルダの順に探します（`GoogleDriveFolders`）

### 1台で2人分を試す手順

`--team-profile=名前` を付けて起動すると、端末 ID・表示名・最近のプロジェクトを別に持つ「2人目」になります（`TeamSettings.userDefault`）。ウィンドウのタイトルに `[名前]` が付きます。

```
& "（展開した場所）\TaskNavi\TaskNavi.exe" --team-profile=test2
```

1. いつもどおり起動し、左上の「プロジェクト ▼」→「新しい共有プロジェクトを作る」で `G:\マイドライブ` の中に作る
2. もう1つを `--team-profile=test2` で起動し、「プロジェクト ▼」→「共有フォルダから参加する」で同じフォルダを開く。ヘッダーが「メンバー 2人」になることを見る
3. 片方の WBS やカンバンでタスクを追加し、数秒でもう片方のどのタブにも出ることを見る。編集画面の担当者の横のボタンから、2人の名前を選べることも見る
4. 片方で編集画面を開いたまま、もう片方で同じタスクの名前を変える。数秒待ってから開いていた方で別の名前にして保存し、ヘッダーにオレンジの「重なった変更」が出ることを見る。押して「〇〇さんの値に戻す」も試す
5. 片方で削除し、もう片方の「プロジェクト ▼」→「変更履歴」に出ること、「元に戻す」で両方に戻ることを見る
6. ブラウザで Google ドライブを開き、`changes` に2つのファイルが上がっていて、「(1)」の付いたコピーができていないことを見る
7. 共有プロジェクトをもう1つ作り、期限が今日のタスクを入れる。「自分だけのタスク」に戻しても、「今日」タブに両方のプロジェクトのタスクが札付きで出ることを見る
8. 期限が今日のタスクを2つ作り、担当者を自分と相手に分ける。「今日」タブで、「自分の担当だけ」がオンなら自分の分だけ、オフにすると両方出ることを見る

この手順で、Google ドライブ上でのファイルの読み書き・自動の読み直し・重なりの検出は確かめられます。別の PC から同期されてくるまでの時間だけは確かめられません。Google Drive for desktop の「アカウントを追加」で2つ目の Google アカウントをつなぐと、別のドライブ文字（H: など）に出るので、そちらから同じフォルダを開けばクラウド経由の同期も1台で試せます。
