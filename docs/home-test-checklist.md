# 配る前に試すチェック表（共有・バックアップ・インポート）

職場に配る前に、家のパソコン1台で「2人で共有する」動きを確かめるための表です。印刷して、終わったら □ に印を付けます。
5章のインポート・エクスポートは Google ドライブが要らないので、職場のパソコンでも試せます。
手順の詳しい説明は `beginner-handbook.md` の16章「1台で2人分を試す手順」にあります。

**家で使うのは、個人の Google アカウントと見本のデータだけにします。仕事のアカウントやデータは使いません。**

## 0. 準備

- [ ] GitHub のリリースから `TaskNavi-1.2.0-windows.zip` をダウンロードし、展開する（場所は `C:\TaskNavi` など短い所）
- [ ] `TaskNavi.exe` をダブルクリックで起動できる。「発行元不明」が出たら「詳細情報」→「実行」。**このとき出た画面と押した所をメモする（配るときの説明書に使う）**
- [ ] Java を入れていないパソコンでも起動できた（入っているかどうかは分からなければ飛ばしてよい）
- [ ] Google Drive for desktop を入れ、個人のアカウントでつなぐ。エクスプローラーに `G:\マイドライブ` が出る
- [ ] アプリをいったん閉じる

## 1. 2人分を起動する

- [ ] 1人目: `TaskNavi.exe` をいつもどおり起動する
- [ ] 2人目: PowerShell で次を実行する。ウィンドウのタイトルに `[test2]` が付く

```powershell
& "C:\TaskNavi\TaskNavi\TaskNavi.exe" --team-profile=test2
```

## 2. 共有を試す

| # | すること | 見ること | 結果 |
|---|----------|----------|------|
| 1 | 1人目:「プロジェクト ▼」→「新しい共有プロジェクトを作る」で `G:\マイドライブ` に作る | エラーなくできる | □ |
| 2 | 2人目:「プロジェクト ▼」→「共有フォルダから参加する」で同じフォルダを開く | 両方のヘッダーが「メンバー 2人」 | □ |
| 3 | 1人目でタスクを追加する | 数秒で2人目の WBS・カンバン・ガント・カレンダーに出る | □ |
| 4 | 編集画面の担当者の横のボタンを押す | 2人の名前から選べる | □ |
| 5 | 1人目で編集画面を開いたまま、2人目で同じタスクの名前を変える。数秒待って1人目で別の名前にして保存 | 1人目のヘッダーにオレンジの「重なった変更」。押して「〇〇さんの値に戻す」ができる | □ |
| 6 | 片方でタスクを削除する | もう片方の「変更履歴」に出る。「元に戻す」で両方に戻る | □ |
| 7 | ブラウザで Google ドライブのプロジェクトのフォルダを開く | `changes` にファイルが2つ。「(1)」の付いたコピーがない | □ |
| 8 | 期限が今日のタスクを2つ作り、担当者を自分と相手に分ける | 「今日」タブの「自分の担当だけ」オンで自分の分だけ、オフで両方 | □ |
| 9 | 2人目でタスクを作り、担当者を1人目の表示名にする | 1人目に Windows の通知「…をあなたの担当にしました」 | □ |

## 3. オフラインと別のアカウント（できれば）

- [ ] Google Drive for desktop を「一時停止」にして両方で別のタスクを変え、再開する。数十秒で両方に両方の変更が出る
- [ ] Google Drive for desktop の「アカウントを追加」で2つ目の Google アカウントをつなぐ（`H:` などに出る）。1つ目のフォルダを2つ目に「編集者」で共有し、2つ目の「共有アイテム」から「ショートカットを追加」する。2人目は `H:\マイドライブ\…` から参加し直して、2-3 と 2-5 をもう一度試す。**同期にかかった秒数をメモする**

## 4. バックアップから戻す

バックアップは、起動した直後に1日1回、その時点のデータを丸ごとコピーして作ります（7日分）。初めての起動ではまだデータがないので作られません。

- [ ] 「自分だけのタスク」に「バックアップの印」というタスクを作り、アプリを閉じる
- [ ] もう一度起動して閉じる。`%APPDATA%\TaskNavi\backups` に `tasknavi-（今日の日付）.db` ができている
- [ ] 起動して「バックアップの印」を削除し、閉じる
- [ ] `%APPDATA%\TaskNavi\tasknavi.db` を `tasknavi-old.db` に名前を変える
- [ ] `backups` の `tasknavi-（今日の日付）.db` を `%APPDATA%\TaskNavi` にコピーし、名前を `tasknavi.db` にする
- [ ] 起動すると「バックアップの印」が戻っている
- [ ] **どこで迷ったかをメモする（配るときの説明書に使う）**

## 5. インポート・エクスポート（職場でもできる）

「置き換え」で取り込むと中身が全部入れ替わるので、いつものデータでは試しません。PowerShell で次のように起動すると、`C:\TaskNaviTest` に試す専用のデータ（見本入り）ができます。この窓から起動した分だけがそこを使います。

```powershell
$env:TASKNAVI_DATA_DIR = "C:\TaskNaviTest"
& "C:\TaskNavi\TaskNavi\TaskNavi.exe"
```

| # | すること | 見ること | 結果 |
|---|----------|----------|------|
| 1 | ヘッダーの「エクスポート」で CSV に書き出し、Excel で開く | 文字化けしない。列は ID・親ID・階層・タスク名・担当者・開始日・終了日・状態・優先度・進捗(%)・メモ | □ |
| 2 | Excel で名前を1つ変え、行を1つ足す（ID は `1001` など重ならない数字、親ID は今ある工程の ID、日付は `2026/11/5`）。「CSV UTF-8」で保存 | 保存できる | □ |
| 3 | 「インポート」で 2 のファイルを選び、「追加」で取り込む | 取り込む前に件数が出る。WBS で、足した行が正しい工程の下に入る | □ |
| 4 | 2 を「CSV（コンマ区切り）」でも保存して取り込む | こちらも文字化けせずに読める | □ |
| 5 | わざと間違えた行を入れる（状態を「保留」、開始日を終了日より後、親ID をない番号） | 取り込む前に、何行目が何の理由で駄目かが出る | □ |
| 6 | タスク名を `=1+1` にしてエクスポートし、Excel で開く | 計算されず文字のまま。取り込み直しても `=1+1` のまま | □ |
| 7 | JSON でエクスポートし、いくつか消してから「置き換え」で取り込む | 書き出したときの中身に戻る | □ |
| 8 | （家で）共有プロジェクトを開いて CSV を「追加」で取り込む | 2人目にも数秒で全部出る | □ |

開発用の PC なら、README の「開発メモ」の `TestDataTool` で `C:\TaskNaviTest` を作ると、見本の代わりに試すためのタスク（期限切れ・長い名前・日付なしなど）が入ります。5 で使う、わざと間違えた行は、同じフォルダの `test-data-bad.csv` にあります。

終わったらアプリを閉じ、`C:\TaskNaviTest` を消せば元どおりです。

- [ ] 「×」や「おかしい」と思った所を、画面の写真と一緒にメモする
- [ ] Google ドライブの試したフォルダは消してよい
