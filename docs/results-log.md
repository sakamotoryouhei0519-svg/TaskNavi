# 使ってみた結果の記録

社内で使い始めてからの様子を書きためる表です。あとで「何を作り、使ってどうなったか」を数字と出来事で話せるようにするためのものです。週に1回、5分で書ける量にしています。

## 書く前の約束

このリポジトリは公開されています。ここに書いたものは誰でも読めます。

- **会社名・人の名前・実際のタスク名やプロジェクト名は書かない。** 人は「メンバー A」「リーダー」のように役割で書く
- 書くのは数と出来事だけにする（「期限切れが 12 件 → 3 件」「重なった変更が 2 回。どちらも戻せた」）
- 画面の写真は載せない。載せるなら見本のデータで撮り直す（README の「開発メモ」）
- 名前入りのメモは、このリポジトリの外（自分の PC のメモなど）に置く
- **公開してよい範囲は、先に会社に確かめる。** 確かめるまでは、この表を埋めても push しない

## 1. 始める前の様子（使い始める前に1回）

使う前の数字がないと、良くなったかどうかを言えません。始める前の1〜2週間で取ります。

| 項目 | 始める前 |
|---|---|
| 今の管理のしかた（Excel・紙・口頭など） | |
| 使う人数 / プロジェクトの数 | |
| 進み具合を確かめるのにかかる時間（1週間で、全員分の合計） | 分 |
| 期限を過ぎて気づいたタスクの数（1週間） | 件 |
| 「誰が持っているか分からない」「言った・聞いていない」が起きた回数（1週間） | 回 |
| 困っていること（3つまで） | |

## 3. 週ごとの記録

毎週同じ曜日に書きます。数はアプリの画面で見られます。

| 週 | 使った人数 | タスクの数 | 期限切れ | 重なった変更 | 不具合・要望 | 使っていた版 | ひとこと |
|---|---|---|---|---|---|---|---|
| 1週目（ / ） | | | | | | | |
| 2週目（ / ） | | | | | | | |
| 3週目（ / ） | | | | | | | |
| 4週目（ / ） | | | | | | | |

見る所:

- 使った人数: 共有プロジェクトのヘッダーの「メンバー ○人」。押すと各自の版も分かる
- タスクの数・期限切れ: 「今日」タブの「期限切れ」の件数。全部の数は CSV にエクスポートした行数
- 重なった変更: ヘッダーのオレンジの「重なった変更 ○件」（戻したり「このままでよい」にした分は消えるので、見た時に数える）
- 変更の量（誰がどれだけ書いたか）: プロジェクトのフォルダの `changes` の中のファイルの行数。1行が1回の変更です（ファイル名に PC の名前が入るので、名前は書き写さない）

```powershell
Get-ChildItem "（プロジェクトのフォルダ）\changes\*.jsonl" | ForEach-Object { (Get-Content $_.FullName).Count }
```

- エラー: 各 PC の `%APPDATA%\TaskNavi\logs` に `ERROR` の行があるか

## 7. 面接やポートフォリオで話す形

上の表がたまったら、次の4つの順で短くまとめます。数字は表から写します。

1. **状況**: 何人のチームで、何を使って、何に困っていたか（1の表）
2. **やったこと**: 何を作り、どう配ったか。なぜその作りにしたか（README の「なぜこの作りにしたか」）
3. **結果**: 使い始めて何がどれだけ変わったか（6の表）
4. **直したこと・学んだこと**: 使われてから出た不具合と要望を、どう直したか（4の表）

例（数字は入れ替える）:

> ○人のチームで、Excel でのタスク管理を TaskNavi に切り替えました。サーバーを置けない職場だったので、Google ドライブの共有フォルダだけで同期する作りにしました。1か月で、期限を過ぎて気づくタスクが週 ○件から ○件に減り、毎週の進み具合の確認が ○分から ○分になりました。使い始めてから出た不具合は ○件で、平均 ○日で直して配り直しました。
